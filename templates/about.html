1. What is an IDS?

An Intrusion Detection System (IDS) is a software application or device that monitors network traffic and computer systems for malicious activity, policy violations, or unauthorized access attempts. Upon detecting suspicious patterns, it alerts system administrators or triggers defensive responses.

2. What is Machine Learning?

Machine Learning (ML) is a branch of Artificial Intelligence where algorithms automatically learn statistical patterns and decision boundaries from historical data (training data) to make predictions on unseen data, without being explicitly programmed with rigid hardcoded rules.

3. How this Project Detects Attacks

Network packets are characterized by statistical features (protocol, connection duration, byte counts, TCP handshake flags, connection rates). The trained Random Forest evaluates these mathematical features simultaneously to distinguish legitimate sessions from DoS attacks, probes, and scans.

4. Why Random Forest was Selected

Random Forest is an ensemble of decision trees utilizing bagging (Bootstrap Aggregation). It excels on tabular network data, handles mixed categorical and continuous variables, is resistant to overfitting, and provides interpretable feature importances ideal for viva defense.

5. The NSL-KDD Dataset

The NSL-KDD dataset is the widely recognized academic benchmark solving redundancy issues in the older KDD Cup 99 dataset. It contains labeled network connection records across normal traffic and major attack families: Denial of Service (DoS), Probing (Scan), U2R, and R2L.

An IDS is a cybersecurity defense tool that monitors network packets or system logs in real-time to detect malicious activities, unauthorized access attempts, and policy violations. It can be Network-based (NIDS) or Host-based (HIDS).

An intrusion is any unauthorized, illegitimate, or malicious action that compromises the confidentiality, integrity, or availability (CIA triad) of a computer network or system (e.g., Denial of Service, brute force login, port scanning).

Traditional signature-based IDS (like Snort) requires manual updates for every attack string and fails completely against novel, mutated, or zero-day attacks. Machine Learning learns general statistical anomalies and connection patterns, allowing it to detect previously unseen attacks without manually written rules.

Random Forest is an ensemble learning method combining multiple decision trees (Bagging). It has key advantages for network data:
  • Handles non-linear relationships and high-dimensional tabular data.
  • Robust against overfitting compared to a single decision tree.
  • Requires less hyperparameter tuning than deep neural networks while achieving 99%+ accuracy.
  • Provides feature importance scores (Gini impurity decrease).

NSL-KDD was developed by the Canadian Institute for Cybersecurity to refine the original KDD Cup 99 dataset. It eliminates redundant and duplicate connection records that previously biased classifiers toward frequent records, providing an unbiased benchmark for academic IDS evaluation.

Features are measurable properties or characteristics extracted from an observation. In our IDS, features include the protocol used (TCP/UDP), connection flags (SF, S0), bytes transferred (src_bytes, dst_bytes), and frequency rates (count of connections in 2 seconds).

Binary classification is a supervised learning task where each input instance is mapped into exactly one of two mutually exclusive classes. In our system, the target classes are NORMAL (benign) and INTRUSION (malicious).

Training Data (80%): Used by the algorithm to build decision rules and learn internal weights.
Testing Data (20%): Strictly held-out data never seen during training, used exclusively to objectively evaluate how well the model generalizes to new traffic.

Overfitting occurs when a model memorizes the training data including noise and quirks, performing poorly on unseen data. We prevented overfitting by using a Random Forest ensemble (which averages predictions across 100 decorrelated trees) and constraining tree growth with max_depth=15.

Accuracy is the proportion of total predictions that were correct: (TP + TN) / (TP + TN + FP + FN). Our model achieves ~99.8% test accuracy.

Accuracy alone can be misleading if classes are imbalanced.
  • Precision: Out of all packets flagged as attacks, how many were truly attacks? TP / (TP + FP). High precision means minimal false alarms.
  • Recall: Out of all actual attacks occurring, how many did the system catch? TP / (TP + FN). High recall means few missed intrusions.
  • F1-Score: The harmonic mean of precision and recall: 2 * (P * R) / (P + R), providing a balanced single performance metric.

A Confusion Matrix is a 2x2 table that categorizes prediction outcomes:
  • True Negative (TN): Normal traffic correctly classified as Normal.
  • False Positive (FP): Normal traffic incorrectly flagged as an Attack (False alarm).
  • False Negative (FN): Attack traffic incorrectly classified as Normal (Dangerous missed intrusion).
  • True Positive (TP): Attack traffic correctly detected as an Intrusion.

The model and preprocessor are saved as binary files (.pkl) using Joblib. When Flask receives an HTTP POST request at /api/predict with JSON network features, it loads the serialized preprocessor to encode and scale the features, feeds them to the loaded Random Forest model's predict() and predict_proba() methods, and returns the result as JSON to the web frontend.

One-Hot Encoding: Converts non-numeric categorical attributes (e.g., protocol: tcp, udp, icmp) into binary indicator columns (0 or 1) so mathematical algorithms can process them without imposing false numerical hierarchies.
Feature Scaling (StandardScaler): Normalizes continuous numerical variables (e.g., src_bytes spanning 0 to 100,000 vs. error rates spanning 0 to 1) to mean 0 and variance 1, preventing large-scale variables from dominating computations.
